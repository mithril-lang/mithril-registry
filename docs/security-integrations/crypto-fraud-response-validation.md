# Crypto fraud response validation

Version 0.1.0 provides local evidence preparation, not an acquisition or recovery service. Cases and incident data stay outside source control. Collection authorization, inference disclosure, jurisdiction and recipient approval remain operator responsibilities.

## Verified contracts

`python3 -m unittest discover -s scripts -p test_crypto_fraud_response.py -v`
exercises retained original bytes and line references, corruption rejection,
owner-scope declarations, input-root/traversal/symlink rejection, duplicates,
SMS epoch parsing and empty/unsupported XML, transaction provenance spoofing,
private permissions and interrupted staging, and installed-profile MCP discovery
and execution via actual subprocesses. All input is synthetic. The complete
Registry test suite runs the same checks in CI.

The [Skill](../../skills/security/mithril-crypto-fraud-response/SKILL.md) includes
the CLI, tool schemas, workflow and profile installer. Registry validates its
frontmatter, references and generated index. Codex's generic Skill validator has
a narrower frontmatter contract than this Registry's required `version` and
`author` fields; Registry validation is the distribution gate.

## Installation and limits

Run the bundled `scripts/install_profile.py --home /absolute/hermes-home`
to review its plan, then append `--apply` to create a fresh profile. Existing
profiles are preserved. The dedicated `crypto-fraud-local` server binds only the
new profile's private case root. A new chat is required for tool discovery;
configure an approved inference provider in that profile before agent dialogue.
No credential cloning, active-profile change, cron, public API or installer
release is required for this local extension.

Root permissions and SHA-256 do not provide encryption, a WORM store, trusted
timestamps, independently authenticated authority or signed custody. Use the
separate Forensic Evidence evaluation kit where those local signing/reviewer
components are needed. Android USB recognition and export parsing do not prove
complete device extraction. LINE/SMS/RCS formats vary; unsupported exports are
kept as opaque attachments or fail explicitly. An identifier match does not
authenticate a natural person, a transaction or an exchange. The server makes
no network requests. Supplied snapshots remain unverified observations.

`fraud_draft` returns checklists and evidence references, not a completed legal
filing. Actual narratives and loss schedules require case facts and human
review. No submission, acknowledgement, freeze, restitution or court decision
is claimed from this local qualification.
