# Mithril Public Code Review (workflow)

This surface composes the `mithril-public-review` skill, plugin, agent, workflow and MCP into the existing Mithril Agent/Desktop profile flow. Runtime artifact: [73d04bf](https://github.com/mithril-lang/mithril-system-one/tree/73d04bfc4160409afb274fdf895d2316c72d19fc). [Execution contract and installation](https://github.com/mithril-lang/mithril-system-one/blob/73d04bfc4160409afb274fdf895d2316c72d19fc/docs/public-code-review-bot.md).

Input: public `owner/repository` plus an exact 40-character commit. The tool verifies source provenance, parses a bounded JavaScript/TypeScript ESM/CommonJS child_process subset and executes `.mith` ontology policies. It also acquires supported npm lockfiles, resolves full OSV advisories, invokes a pinned operator-owned private version matcher, and enriches through Knowledge. Live NVD/KEV/EPSS enrichment is verified with independent manifest pins; the combined catalog index remains stale. Result is always `review_incomplete`; candidates require human review. No target code execution, inference, private target-repository acquisition, GitHub writes or disclosure.

The `mithril-public-code-review` bot profile uses English and api.mithril.fund for future conversations. Install it with the artifact's `scripts/install-public-review-profile.py --home /absolute/hermes/home --apply`; credentials belong to that profile and are configured separately. No active-profile switch, gateway startup or scheduled jobs occur. Deterministic tool readiness is verified; a live provider conversation is qualified for the independently configured operator profile.

Native Agent tested on macOS with 0.21.5+4485.g3da66ca.dirty. Linux compatibility is not qualified. MCP is local stdio 2025-06-18, not a hosted URL. Workflow runs exactly one immutable repository review and stops on failure/unknown without retries.

Dependency setup requires separately authorized private `security-core` access; no proprietary source is distributed. See the [dependency runtime contract](https://github.com/mithril-lang/mithril-system-one/blob/73d04bfc4160409afb274fdf895d2316c72d19fc/docs/dependency-ontology-evaluation.md). Missing/stale feeds never mean safe; no host probes, SCAP fixes or automatic merging. The upgraded tool was qualified through native Agent dispatch; the model-conversation qualification predates this dependency release.

Use `mithril_scap_review` with supplied XML for namespace-qualified SCAP/ARF OVAL/XCCDF results. Unknown outcomes remain gaps; definition-only content does not evaluate a host. Use `mithril_dependency_upgrade` with SHA-256-bound root package.json/package-lock.json for isolated direct same-major npm patches and OSV/Mithril re-evaluation. Both tools are provided by the pinned MCP/plugin; the workflow's fixed command still performs a single repository review. The upgrade tool returns files only, with no project writes, compatibility testing or merge. Explicit local application is available separately through the CLI `--apply-dir` with clean tracked files and base hashes. [Scope and qualification](https://github.com/mithril-lang/mithril-system-one/blob/73d04bfc4160409afb274fdf895d2316c72d19fc/docs/scap-and-remediation.md).

0.5.0 adds cooperative exclusive local apply and private recovery journaling. Explicit local CLI `--recover-dir` requires a dead original process, unchanged Git HEAD and recorded file digests; operator edits refuse. Recovery is not a bot/MCP filesystem capability and never runs models, feeds or scripts. Manifest/lock specs and duplicate JSON keys are checked; lock-entry deltas are recorded and differing reported SCAP hosts refuse. Power loss and non-cooperating writers are unqualified. [Reliability and local CI](https://github.com/mithril-lang/mithril-system-one/blob/73d04bfc4160409afb274fdf895d2316c72d19fc/docs/security-maturity-0.5.0.md).
